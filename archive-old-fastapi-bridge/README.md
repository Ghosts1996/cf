# VPN onLine — API-мост (backend bridge)

## Что это
Небольшой FastAPI-сервис, который должен встать МЕЖДУ мобильным/десктоп-приложением
и твоей существующей связкой: Telegram-бот (форк 3xui-shopbot) + панель 3x-ui +
платёжные провайдеры (YooKassa, CryptoBot, Heleket).

Сейчас у тебя это работает как Telegram-бот. Приложению нужен REST API — этот
проект даёт СКЕЛЕТ такого API с правильной структурой эндпоинтов, но БЕЗ реальных
интеграций (это невозможно сделать без доступа к твоему серверу, боту и ключам
провайдеров — я их не имею и не должен иметь).

## Что реально нужно доделать тебе / твоему бэкенд-разработчику
1. `app/services/xui_client.py` — подставить реальный адрес панели 3x-ui,
   логин/пароль или сессионный токен, и вызовы её API (создание/продление клиента,
   получение статистики). Готовые open-source обёртки под 3x-ui API есть на GitHub —
   можно переиспользовать вместо написания с нуля.
2. `app/services/payments.py` — перенести туда уже готовую логику из твоего бота
   (создание счёта YooKassa/CryptoBot/Heleket, проверка вебхука по секрету).
   Секреты (Shop ID, Secret Key, CryptoBot Token) — только в `.env`, никогда не в коде
   и не в репозитории.
3. Хранилище пользователей — сейчас в скелете in-memory (для примера). Нужна
   настоящая БД (Postgres/SQLite) — таблицы users, orders, keys.
4. Авторизация — сейчас упрощённый email+код-заглушка. Для продакшена — либо
   Telegram Login Widget (раз у тебя уже вся система вокруг Telegram), либо
   полноценный email+OTP.

## Что проверено
- Структура эндпоинтов, схемы запросов/ответов (Pydantic) — логически
  непротиворечивы, сервис поднимается локально (`uvicorn app.main:app --reload`).
- Не проверено и не может быть проверено без реального сервера: обращение к
  реальному 3x-ui, реальные платежи, реальные вебхуки провайдеров.

## Запуск
```bash
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить реальными значениями
uvicorn app.main:app --reload --port 8000
```

## Эндпоинты (v1)
| Метод | Путь | Назначение |
|---|---|---|
| POST | /v1/auth/request-code | отправить код входа на email |
| POST | /v1/auth/verify | подтвердить код, получить токен |
| GET  | /v1/keys | список ключей пользователя |
| POST | /v1/keys/{id}/extend | продлить ключ (создаёт заказ на оплату) |
| GET  | /v1/plans | список тарифов (7/30/90/180 дней) |
| POST | /v1/orders | создать заказ на покупку нового ключа |
| GET  | /v1/orders/{id} | статус заказа |
| POST | /v1/webhooks/yookassa | вебхук YooKassa |
| POST | /v1/webhooks/cryptobot | вебхук CryptoBot |
| GET  | /v1/servers | список локаций/серверов |
