# Настройка туннеля на каждой платформе (пакет `flutter_singbox_client`)

> [ИСПРАВЛЕНО] Этот файл раньше описывал предыдущий пакет `flutter_vless`
> (Xray-core) — от него отказались (см. докстринг в
> `lib/services/tunnel_service.dart`): одна и та же подписка стабильно не
> поднимала интернет через Xray-core based клиенты, но стабильно работала
> в Hiddify (ядро sing-box). Сейчас туннель реально поднимается через
> `flutter_singbox_client` (то же ядро sing-box, что у Hiddify) —
> `SingboxClient().initialize() → requestVPNPermission() → checkConfig() →
> connect(SessionOptions(...))`, статус — `serviceStateStream`/
> `trafficStatsStream`/`faultStream`. Dart-часть (`tunnel_service.dart`,
> `connect_screen.dart`) полностью готова и рабочая.

## 0. Важно — на сегодня пакет поддерживает ТОЛЬКО Android

На момент написания (см. pub.dev/packages/flutter_singbox_client)
`flutter_singbox_client` официально поддерживает только Android; iOS и
macOS — «в разработке», Windows/Linux — «в планах» у автора пакета. Это
не решается правкой .dart-файлов — платформенного нативного кода для
iOS/macOS/Windows этот пакет пока не предоставляет вообще, поэтому:
- **Android** — собирается и работает полностью, это основная целевая
  платформа CI (`.github/workflows/build-android.yml` собирает именно
  Android APK).
- **iOS/macOS/Windows/Linux** — приложение соберётся (UI, авторизация,
  покупка ключей, список серверов — всё это платформонезависимый Dart/
  Flutter код), но кнопка "Подключить" не поднимет реальный VPN-туннель,
  пока сам пакет (или альтернативный пакет для конкретной платформы) не
  добавит туда поддержку. Как только `flutter_singbox_client` (или его
  автор) добавит iOS/macOS-бэкенд — обновление versions в `pubspec.yaml`
  и внимательная проверка API (имена методов иногда чуть отличаются
  между релизами) должны включить это без переписывания
  `tunnel_service.dart` с нуля, так как публичный API пакета уже
  спроектирован платформонезависимым.

## 1. Лицензия — GPL-3.0, а не MIT

В отличие от `flutter_vless` (MIT), `flutter_singbox_client` — GPL-3.0.
Раз репозиторий планируется открытым (см. `SECURITY.md`), это не
проблема само по себе, но накладывает требования GPL на сборку, в
которую пакет статически слинкован при *распространении* (не при личном
использовании) — если планируешь распространять готовый APK за пределами
"я тестирую сам", проконсультируйся с юристом насчёт условий (обычно
нужна доступность исходников приложения, что у тебя и так уже
выполняется открытым репозиторием, или явное указание лицензии в
интерфейсе "О приложении").

## 2. Android — что уже сделано и что проверить руками

Уже сделано в этом репозитории:
- `android/app/src/main/AndroidManifest.xml`: `INTERNET`,
  `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`,
  `POST_NOTIFICATIONS`, `QUERY_ALL_PACKAGES` (для `installed_apps` на
  экране split-tunnel) — все уже прописаны.
- `minSdk = 23`, `compileSdk = 36`, `targetSdk = flutter.targetSdkVersion`
  в `android/app/build.gradle.kts` — совместимо с минимальными
  требованиями пакета (см. README пакета: `minSdk 23`).
- `.github/workflows/build-android.yml` собирает debug- и release-APK,
  подставляет `SHOPBOT_API_KEY`/`API_BASE_URL` из Secrets, генерирует
  фирменную иконку (`dart run flutter_launcher_icons`) и подписывает
  release-сборку реальным keystore, если секреты
  `ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD`/
  `ANDROID_KEY_ALIAS`/`ANDROID_KEY_PASSWORD` заданы — иначе собирает
  unsigned release (для тестов, не для Google Play).

Проверить руками при первом реальном запуске:
- [ ] `flutter pub get` резолвится без ошибок (пакет реально существует
      на pub.dev под именем и версией, указанными в `pubspec.yaml` — если
      автор опубликует 2.x с breaking changes, версию в pubspec.yaml
      нужно будет поднять осознанно, а не автоматически).
- [ ] Компилятор не ругается на имена `ServiceState`/`TrafficStats` в
      `tunnel_service.dart` (`_mapServiceState`, `trafficStatsStream`
      listener) — в README пакета на момент написания этого файла точные
      имена enum-значений не были опубликованы полностью, сопоставление
      сделано по наиболее вероятным именам через `toString()` (устойчиво
      к небольшим отличиям), но при обновлении версии пакета стоит
      свериться с фактическим кодом в
      `~/.pub-cache/hosted/pub.dev/flutter_singbox_client-*/lib/`.
- [ ] Собери и поставь на **реальный телефон** (не эмулятор — VPN на
      эмуляторе Android часто ведёт себя иначе, чем на реальном
      устройстве): `flutter run -d android` или скачай APK из артефактов
      GitHub Actions.
- [ ] Нажми "Подключить" → должен появиться системный диалог "Разрешить
      VPN-подключение" → после разрешения — постоянное уведомление о
      VPN-статусе в шторке (требует `POST_NOTIFICATIONS`, уже добавлено).
- [ ] Проверь реальный внешний IP на телефоне до и после подключения
      (например через браузер) — должен смениться на IP выбранной
      локации.
- [ ] Отключение реально гасит VPN-иконку в шторке — не остаётся
      "подключено" в интерфейсе при разорванном туннеле.
- [ ] На экране "Split-туннелирование" список реальных приложений
      устройства загружается без исключения (если кинет ошибку — почти
      наверняка не хватает `QUERY_ALL_PACKAGES`, но он уже в манифесте).

## 3. iOS / macOS — заблокировано на уровне пакета, не только настройки

Пока `flutter_singbox_client` официально не поддерживает iOS/macOS (см.
пункт 0), настраивать Network Extension/App Group в Xcode бессмысленно —
подключать сейчас нечего, нативной части под эти платформы у самого
пакета ещё нет. Когда автор добавит поддержку — типовой процесс для
VPN-пакетов на iOS такой (сохранено для справки на будущее):
1. Apple Developer аккаунт (платный — Network Extension entitlement не
   выдаётся на бесплатном) → App Group.
2. File → New → Target → **Network Extension** → Packet Tunnel Provider
   в Xcode, тот же App Group у основного таргета и у Tunnel-таргета.
3. Тестируется только на реальном устройстве — симулятор iOS не поднимает
   системный VPN-туннель.

## 4. Windows/Linux — не поддерживается пакетом на сегодня

Аналогично iOS/macOS (см. пункт 0) — автор пакета указывает Windows/Linux
как "в планах". До этого момента Windows/Linux-сборки Flutter-приложения
будут работать как обычный клиент личного кабинета (вход, покупка,
список ключей/серверов), но без реального VPN-туннеля.

## 5. Если что-то не работает на реальном устройстве

Пришли точный текст ошибки (`lastError` в интерфейсе, либо `adb logcat`
для более полной картины) — большинство проблем на этом этапе либо в
точном названии enum/поля пакета (пункт 2 выше), либо в конкретном
VLESS+Reality параметре подписки, который стоит сверить вручную.
