# VPN onLine — клиентское приложение и патч бэкенда

**VPN onLine** — мобильный VPN-клиент (Flutter, Android; iOS/macOS/Windows —
код готов, платформенная настройка не завершена) для сервиса **vpnonline.su**.
Приложение поднимает туннель по протоколу **VLESS + Reality** через
встроенное ядро **sing-box** и работает в связке с уже существующим
Telegram-ботом/сайтом продаж подписок (проект `shopbot`), у которого есть
собственный Flask JSON API.

Репозиторий содержит две части:
- `app/` — само Flutter-приложение;
- `backend-patch/` — исправления безопасности для двух файлов бэкенда
  `shopbot` (`api.py`, `database.py`), которые нужно вручную скопировать на
  сервер.

---

## Архитектура

Приложение обращается **напрямую** к реальному Flask API бота
(`shopbot/src/shop_bot/webhook_server/api.py`, префикс `/api/v1/...`,
базовый адрес — `https://api.vpnonline.shop/api/v1`). Отдельного
промежуточного сервера у приложения нет.

В репозитории также лежит каталог `archive-old-fastapi-bridge/` — более
ранняя, отдельная реализация API (FastAPI), которая была написана под
несуществующие на сервере пути и **не используется** текущим приложением.
Она оставлена только как архив и **не должна разворачиваться**.

Авторизация запросов — двухуровневая:
- заголовок `X-API-Key` — статический ключ сборки (передаётся при компиляции
  через `--dart-define=SHOPBOT_API_KEY=...`, не хранится в исходном коде);
- заголовок `Authorization: Bearer <token>` — персональный токен сессии
  пользователя, выданный сервером при входе/регистрации и хранящийся на
  устройстве в защищённом хранилище ОС (Keychain на iOS/macOS, Keystore на
  Android — не в обычных настройках приложения).

## Функциональность приложения

**Онбординг и вход**
- Разовый онбординг (3 экрана) при первом запуске, флаг хранится локально.
- Полноценный экран входа: логин по email/паролю, регистрация с кодом
  подтверждения на почту, восстановление пароля по коду. При старте
  приложение пробует восстановить сессию из защищённого хранилища и не
  просит логиниться заново, если токен ещё жив.

**Подключение (главный экран)**
- Реальное подключение/отключение VPN-туннеля (VLESS + Reality, ядро
  sing-box), живые счётчики скорости приёма/отдачи и таймер длительности
  сессии.
- Два режима работы: полноценный системный VPN (TUN-интерфейс) и
  proxy-only режим (локальный SOCKS5/HTTP-прокси на 127.0.0.1:2080, без
  системного VPN-интерфейса).
- Запрос системного разрешения на VPN перед подключением, с понятной
  ошибкой вместо краша, если пользователь отказал.
- Автоматический перебор всех серверов из активной подписки, если
  выбранный не отвечает, с реальной проверкой того, что интернет
  действительно идёт через туннель (а не только «интерфейс поднялся»).
- Поддержка ссылок вида `vless://`, URL подписки (в т.ч. в base64) и
  готового JSON-конфига sing-box.

**Мои ключи**
- Список купленных ключей с реальными полями сервера (дата окончания,
  лимит устройств, строка подключения); докупка дополнительных устройств
  на ключ; проверка ключа/подписки без подключения («сколько серверов
  реально нашлось»); возможность вставить свою ссылку на подписку/`vless://`
  вручную, в обход ключей из личного кабинета.

**Тарифы и оплата**
- Покупка нового ключа или продление существующего с оплатой с внутреннего
  баланса аккаунта (не банковской картой напрямую — на этом шаге сервер
  просто списывает баланс).
- Отдельный экран пополнения баланса (ЮKassa / CryptoBot) — деньги на
  баланс и покупка ключа за баланс разведены как два разных шага, как это
  устроено на сервере.

**Серверы**
- Список локаций подтягивается с сервера (таблица хостов бота) — новая
  локация, добавленная на бэкенде, появляется в приложении сама, без
  правок кода. Есть избранное (сохраняется на устройстве).

**Split-туннелирование**
- Список установленных приложений на устройстве (Android), выбор
  конкретных приложений, которые идут в обход VPN; выбор реально
  применяется к конфигу sing-box при следующем подключении.

**Безопасность**
- Kill Switch с автопереподключением при обрыве связи (число попыток
  настраивается).
- Выбор DNS-резолвера (Cloudflare/Google/AdGuard/Quad9), опциональная
  блокировка рекламных/трекинговых доменов, опциональный обход DPI
  (фрагментация TLS-хендшейка).

**Реферальная программа**
- Персональная реферальная ссылка, счётчик приглашённых, накопленный
  реферальный доход — всё приходит вместе с профилем одним запросом.

**Настройки и поддержка**
- Автоподключение, «умное» подключение на Wi-Fi, выход из аккаунта.
- Ссылки на сайт, Telegram/MAX-бота, бота поддержки и новостной канал.

## Безопасность бэкенда — что исправлено патчем

Полный отчёт с доказательствами — `backend-patch/REPORT.md`. Кратко:
- убран рабочий пароль от почты рассылки, зашитый прямо в исходном коде
  как значение по умолчанию (теперь только из `.env`, иначе рассылка не
  отправляется, а не тихо работает на скомпрометированном пароле);
- убран публичный ключ API по умолчанию (без `SHOPBOT_API_KEY` в `.env`
  сервер теперь отвечает ошибкой, а не принимает всем известную строку);
  сравнение ключа переведено на защищённое от timing-атак сравнение;
- закрыта возможность перебором email узнавать зарегистрированных
  пользователей через ответ восстановления пароля;
- закрыта гонка при списании баланса (TOCTOU) при покупке/продлении ключа
  и докупке устройств — списание переведено на уже существовавшую в коде,
  но не подключённую атомарную функцию;
- email-адреса маскируются в логах вместо хранения в открытом виде.

## CI/CD

- `.github/workflows/build-android.yml` — сборка релизного APK, ключ
  API и адрес сервера передаются через `--dart-define` из GitHub Secrets
  (`SHOPBOT_API_KEY`, `API_BASE_URL`), сборка подписывается ключом из
  секретов (`ANDROID_KEYSTORE_BASE64` и связанные).
- `.github/workflows/ai-coder.yml` — вспомогательный ручной workflow
  (`workflow_dispatch`), который по текстовому запросу собирает весь код
  Flutter-приложения и отправляет его во внешнюю AI-модель для
  автоматических правок; требует секреты `AITUNNEL_BASE_URL`/
  `AITUNNEL_API_KEY`. Полезен для быстрых точечных правок без ручного
  редактирования, но результат перед сборкой стоит просматривать как
  обычный внешний PR.
- `.github/workflows/scaffold-platforms.yml` — вспомогательный workflow
  для генерации недостающих платформенных проектов Flutter.

## Что нужно сделать вручную (секреты, которые нельзя вписать за вас)

1. Скопировать `backend-patch/api.py` и `backend-patch/database.py` в
   `shopbot/src/shop_bot/webhook_server/` на сервере и перезапустить бота.
2. Добавить переменные из `backend-patch/ENV_ADDITIONS.env` в `.env` бота;
   пароль от почты — обязательно новый, старый считается скомпрометированным.
3. При необходимости выполнить `backend-patch/set_payment_settings.py` —
   он пишет платёжные настройки (ЮKassa/CryptoBot) прямо в БД бота, это не
   `.env`-переменные.
4. Задать GitHub Secrets для сборки (`SHOPBOT_API_KEY`, `API_BASE_URL`,
   ключ подписи Android).
5. Платформенная настройка VPN для iOS/macOS/Windows (App Group + Network
   Extension, `xray.exe`) — не делается правкой `.dart`-файлов, см.
   `app/NATIVE_SETUP.md`.
