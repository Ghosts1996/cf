# Что изменилось во второй итерации

Честная сводка — что сделано, что проверено, что нет.

## Backend

**Безопасность**
- `auth.py`: `random.randint` → `secrets.randbelow` для генерации кода входа
  (криптостойкий генератор вместо предсказуемого).
- `auth.py`: добавлен rate-limit по IP на `/request-code` (10 запросов/10 мин)
  в дополнение к существующему лимиту по email — раньше атакующий мог
  перебирать код с разных email одновременно.
- `auth.py`: сравнение кода через `secrets.compare_digest` (защита от
  timing-атак при сравнении строк, раньше было `==`).

**Монетизация**
- `plans.py`: добавлен бесплатный пробный тариф (3 дня, без привязки
  карты) + расчёт "выгоды в %" для длинных тарифов — считается на
  бэкенде, чтобы фронт не мог показать неверную цифру.
- `orders.py`: пробный тариф обрабатывается отдельно — сразу выдаёт ключ
  без похода к платёжному провайдеру, с защитой "один раз на аккаунт".
- `xui_client.py`: реализованы `create_client`/`extend_client` (раньше
  были `NotImplementedError`). Основаны на общепринятом API 3x-ui
  (`POST /panel/api/inbounds/addClient` и `.../updateClient/{id}`) —
  **это лучшее предположение, не проверенное на реальной панели**, формат
  `settings` как JSON-строки — частый источник расхождений между
  версиями/форками панели.
- `webhooks.py`: раньше после подтверждения оплаты стоял пустой `TODO` —
  заказ помечался оплаченным, но ключ реально не выдавался. Теперь
  вызывается `_fulfill_order` → создание/продление клиента в 3x-ui +
  запись в `shop_db`.
- `shop_db.py`: добавлены `insert_key_row`, `update_key_expiry`,
  `has_used_trial`, `mark_trial_used`, `get_or_create_referral_code`,
  `get_referral_stats`. **Все — на предполагаемой схеме** (см. комментарии
  `ПРЕДПОЛОЖЕНИЕ` в файле); часть требует добавить колонки в таблицу
  `users` (`trial_used`, `referral_code`, `referred_by`) через миграцию
  в твоём боте, если их там ещё нет.
- Новый роут `referral.py` — код/ссылка/счётчик приглашённых.
  Начисление бонуса за приглашённого сознательно НЕ реализовано — это
  бизнес-решение (фиксированные рубли? % от оплаты? дни подписки?),
  которое должен принять ты.

## Flutter-приложение

- `plans_screen.dart`: тарифы теперь тянутся из `/v1/plans`, а не
  дублируются в коде (был реальный риск расхождения цены в UI и при
  оплате). Кнопка покупки реально вызывает `createOrder` и открывает
  `payment_url` в браузере; для пробного тарифа — сразу активирует.
- `connect_screen.dart`: кнопка "Подключить" теперь заблокирована, если у
  пользователя нет активного ключа (раньше была активна всегда — UI лгал
  о возможности подключения). Индикатор задержки стал живым (замер через
  реальный HTTP round-trip к бэкенду — это НЕ пинг до самого VPN-узла,
  честно помечено в коде).
- `keys_screen.dart`: добавлены состояния загрузки/ошибки-с-повтором/пусто.
  Кнопка "Продлить" ведёт на экран тарифов. Также исправлено расхождение:
  экран ожидал поля `devices_used`/`devices_max`/`days_left`, которых
  бэкенд не отдаёт — приведено к реальной схеме ответа `/v1/keys`.
- `onboarding_screen.dart` (новый): 3 экрана при первом запуске, флаг —
  в `SharedPreferences`.
- Реферальный экран в меню — раньше пункт никуда не вёл.
- Новые зависимости: `shared_preferences`, `url_launcher`.

## Что НЕ проверено и не может быть проверено в этой среде
- Сеть в контейнере отключена → `pip install`/`flutter pub get` не
  выполнялись. Python-код прошёл `py_compile` (синтаксис ОК), но не
  реальный `uvicorn`-прогон. Dart-код проверен на баланс скобок вручную,
  но не компилировался — прогони `flutter analyze` у себя перед сборкой.
- Реальные вызовы 3x-ui API (`create_client`/`extend_client`) — сверь
  с логами твоей панели, формат `settings` может отличаться на твоём форке.
- Реальная схема таблиц твоего бота — все SQL остаются на предположениях,
  явно помеченных в коде.
- Нативный VPN-туннель, push-уведомления об истечении ключа, биометрический
  лок приложения, виджет на главном экране — не входят в этот скелет,
  требуют отдельной нативной работы на каждой платформе (не текстовая
  правка, а Xcode/Android Studio/Visual Studio + тестовые устройства).
